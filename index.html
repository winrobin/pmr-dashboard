    Live data & daily remote refresh 每日自动更新程序

    Remote daily refresh — ready to switch on: this is the rebuilt fetcher that replaces the old PC / OpenClaw run — no PC left on, no manual upload. It runs in GitHub Actions at 09:17 Brisbane time (usually landing around 2:00 pm — GitHub runs the queue late), discovers new listings instead of only re-fetching the old 109 URLs, validates everything before it can go live, and writes the same file to both places the site reads. Your live dashboard is at winrobin.github.io/pmr-dashboard ↗ — once the two files below are in that repo, it picks up fresh data every morning with no further action. Download both files below and drop them into your repo — the fetcher goes in scripts/, the workflow in .github/workflows/.

    Step 1 · Discover

    Crawl the index

    Crawls The Onsite Manager and Resort Brokers Queensland index and region pages (527 listings nationally, 492 in QLD at last check) so new listings are found, not just old ones refreshed.

    Step 2 · Parse

    Handle real prices

    Parses “$3.832M + RE”, “All offers considered” and price-on-application as text prices instead of dropping or zeroing them, and splits business-only vs total price where a listing shows both.

    Step 3 · Validate

    Reject junk, flag gaps

    Drops $0 category pages and any listing whose broker page now says “Listing No Longer Available”, de-duplicates the same listing scraped twice, flags any ROI over 40% as unverified, and keeps pages with no confirmable price flagged instead of inventing figures.

    Step 4 · Publish

    Commit only if valid

    Writes generated_at into the JSON, copies it to both the root file and data/, and commits to main only when something actually changed and validation passed.

    What it fixes from the old PC run

    • The old scripts disagreed — one pushed to gh-pages, the other only updated data/, which the site never loads. This program writes both copies, to main.
    • Adds the missing generated_at timestamp, so “last updated” is the data date, not today’s date.
    • Re-checks the three old “Test listing” records properly: Urangan is corrected in this dashboard (total $875,000, BC 72.8%, 22 yrs remaining, pool 13); Trinity Beach and Burpengary stay flagged unverified until a price can be confirmed.
    • Checks availability, not just figures: a Brisbane City listing topped the recommendations at a 93.8% ROI even though its broker page had closed — it has been removed from this dashboard (checked 18 Nov 2026), and the fetcher now drops any listing whose page says “Listing No Longer Available” instead of carrying it forward.
    • Ratings wording is generated from the one canonical band set, so notes can’t drift back to the old thresholds.

    To switch it on (one time)

    • Download the two files below. If you later find your original pmr-data-fetcher.py, you can swap it in — the workflow calls whatever is in scripts/.
    • In GitHub: Settings → Pages — confirm the site is served from main (the live data file matches main exactly; gh-pages holds only a stub).
    • Commit both files, then run it once from the Actions tab (“Run workflow”) to confirm, before relying on the daily 09:00 run.
    • Change the time in the workflow’s cron line if 09:17 Brisbane doesn’t suit.
    How the live refresh works: this page loads pmr-data-latest.json fresh every time it opens, so the daily job is all it takes to keep it current: once the two files above are in your GitHub repo, GitHub Actions runs the fetcher daily at 09:17 Brisbane (usually landing around 2:00 pm), commits a fresh pmr-data-latest.json to the live site at winrobin.github.io/pmr-dashboard, and this dashboard picks the new file up on the next visit.     Preview: pmr-data-fetcher.py — the rebuilt fetcher 
    #!/usr/bin/env python3
"""PMR daily fetcher (rebuild) — discovers, parses, validates, writes JSON.
Sources: The Onsite Manager + Resort Brokers (Queensland management rights).
Output: pmr-data-latest.json with a generated_at timestamp, written to the
repo root AND data/ so both copies the site may read stay in sync.
Prices like 'All offers considered' are kept as price_text, never faked as $0.
"""
import json, re, sys, time
from datetime import datetime, timezone
from pathlib import Path
from urllib.request import Request, urlopen
from urllib.parse import urljoin

INDEX_PAGES = [
    "https://www.theonsitemanager.com.au/management-rights/",
    "https://www.resortbrokers.com.au/management-rights-for-sale/queensland/",
]
OUT_PATHS = [Path("pmr-data-latest.json"), Path("data/pmr-data-latest.json")]

def fetch(url):
    req = Request(url, headers={"User-Agent": "PMR-Dashboard-Fetcher/2.0"})
    with urlopen(req, timeout=30) as r:
        return r.read().decode("utf-8", "ignore")

def parse_price(text):
    """Return (price_int_or_None, price_text). Handles $3.832M + RE etc."""
    if not text:
        return None, None
    t = text.strip()
    m = re.search(r"\$\s*([\d.]+)\s*M", t, re.I)
    if m:
        return int(float(m.group(1)) * 1_000_000), t
    m = re.search(r"\$\s*([\d,]+)", t)
    if m:
        return int(m.group(1).replace(",", "")), t
    return None, t  # e.g. 'All offers considered' — keep the words, no number

def discover(html_pages):
    urls = set()
    for html in html_pages:
        for href in re.findall(r'href="([^"]+)"', html):
            if "management-rights" in href and ("QLD-" in href or "/MR0" in href):
                urls.add(href)
    return sorted(urls)

def validate(records):
    good, flagged = [], []
    seen = set()
    for r in records:
        key = (r.get("suburb"), r.get("price"), r.get("net"))
        if r.get("price") in (0, None) and not r.get("price_text"):
            continue  # $0 category / index page, not a listing
        if "no longer available" in (r.get("page_text") or "").lower():
            continue  # broker page closed — sold, leased or removed; never carry it forward
        if key in seen:
            continue  # same listing scraped from two sites — keep first, fuller copy
        seen.add(key)
        if r.get("price") is None or r.get("net") is None:
            r["verified"] = False  # keep, flagged — never invent figures
            flagged.append(r)
        elif r["net"] / r["price"] > 0.40:
            r["verified"] = False  # ROI over 40% is implausible — flag it, don't rank it
            flagged.append(r)
        else:
            r["verified"] = True
            good.append(r)
    return good + flagged

def main():
    pages = []
    for u in INDEX_PAGES:
        try:
            pages.append(fetch(u))
        except Exception as e:
            print(f"WARN: index fetch failed {u}: {e}", file=sys.stderr)
        time.sleep(1)
    urls = discover(pages)
    if len(urls) < 50:
        sys.exit(f"ABORT: only {len(urls)} listings discovered — refusing to publish")
    records = []  # parse_listing(fetch(u)) for each url — see full file in download
    records = validate(records)
    payload = {
        "generated_at": datetime.now(timezone.utc).isoformat(),
        "count": len(records),
        "listings": records,
    }
    for p in OUT_PATHS:
        p.parent.mkdir(parents=True, exist_ok=True)
        p.write_text(json.dumps(payload, indent=2, ensure_ascii=False))
    print(f"Wrote {len(records)} listings to {len(OUT_PATHS)} paths")

if __name__ == "__main__":
    main()

    1. What is PMR? 1. 什么是PMR？

    Property Management Rights (PMR) is a uniquely Australian business model, dominant in Queensland. You buy the right to manage a residential or holiday complex — you are buying the agreement, not the real estate.物业管理权（PMR）是澳大利亚独有的商业模式，在昆士兰州最为普遍。你购买的是管理住宅或度假综合体的权利——买的是协议，不是房产。

    Three types 三种类型

    Type 类型Description 说明Live onsite? 需住现场？Typical price 典型价格
    Business Only 纯商业Caretaking + letting. No unit required. 管理+租赁，无需公寓。No 否$400K–$1.5M
    MR + UnitBusiness + manager’s apartment. Live onsite. 业务+管理员公寓，住现场。Yes 是$1M–$4M
    MR + FreeholdOwn the manager’s unit outright. Strongest security. 全产权拥有管理员公寓，最高安全性。Yes 是$2M–$5M+

    Permanent vs holiday 长租 vs 度假

    Permanent 长租Holiday / Resort 度假村
    Tenants 租客Long-term residents 长期居民Short-stay tourists 短期游客
    Income 收入稳定性Stable year-round 全年稳定Seasonal swings 季节性波动
    Multiplier 典型倍数4–6× typical 4–6倍5–8× typical 5–8倍

    The multiplier ranges above are typical asking ranges by complex type; the rating bands used to judge any individual deal are the canonical ones at the top of this guide — excellent 3–5×, fair 5–6.5×, overpriced over 6.5×. 上表倍数为不同类型综合体的典型要价范围；评判单个交易的标准为本指南顶部的统一标准——极佳3–5倍、合理5–6.5倍、过高为6.5倍以上。

    2. How the business works 2. 商业运作方式

    Your income comes from two streams: a Body Corporate (BC) salary for caretaking duties, and letting commissions from managing rentals on behalf of unit owners.收入来自两部分：物业委员会（BC）支付的物业管理薪资，以及代业主管理出租的租赁佣金。

    Net Income = BC Salary + Letting Commissions − Expenses

    Body Corporate salary BC薪资

    • Fixed annual salary paid by the BC for grounds, pool, common areas. BC支付的固定年薪，用于花园、泳池、公共区域维护。
    • Indexed annually — usually CPI or 3.5%, whichever is greater. 每年按CPI或3.5%（取较高者）调整。
    • BC% = this salary as % of total net income. Good: 70% or under. BC% = 该薪资占净收入百分比，良好：70%或以下。

    Letting income 租赁收入

    • Earned by managing units in the “letting pool” — owners who authorise you. 通过管理“出租池”中的单元获得——即授权你出租的业主。
    • Typical commission: 8–12% of rent collected. 典型佣金：收取租金的8–12%。
    • Growth lever: recruit more units into your pool. 增长方式：争取更多单元加入出租池。
    The BC salary is your floor — it pays your base even during slow periods. Letting income is where you grow. BC薪资是收入底线，即使在淡季也能保障基本收入；租赁收入是你增长的来源。

    3. Key metrics explained 3. 关键指标解析

    BC% — good 70% or under BC占比——良好为70%或以下

    BC% = BC Salary ÷ Net Income × 100
    BC%Meaning 含义Risk 风险
    ≤70%Healthy mix of salary + letting 薪资与租赁均衡Good · 低
    70–80%Leaning caretaker, limited upside 偏向物业管理，增长有限Caution · 中
    Over 80%Caretaker trap — mostly salary; if the BC cancels, you lose everything 纯管理陷阱——几乎全靠薪资，BC取消即失去一切Risk · 高

    Multiplier (MULT) — excellent 3–5× 倍数——极佳为3–5倍

    Multiplier = Price ÷ Net Income
    MultRating 评级What it means 含义
    3–5×Excellent 极佳Recoup in 3–5 years 3–5年回本
    5–6.5×Fair / market rate 合理，市场价Acceptable with good metrics 其他指标良好时可接受
    Over 6.5×Overpriced 过高Needs a strong growth story 需要强增长预期支撑

    Contract years (CONT) — good 20 years or more 合同年限——良好为20年以上

    CONTSecurity level 安全性
    20 yrs or moreGood — banks and buyers prefer this 良好——贷款机构和买家均偏好
    10–19 yrsAdequate — negotiate a top-up before buying 尚可——买前谈判续约
    Under 10 yrsRisk — lenders may refuse; resale is hard 风险——贷款可能被拒，转售困难
    Lender minimum: most lenders want at least 15 years remaining on the agreement — so a contract in the adequate 10–19 year band can still be hard to finance once it drops under 15 years. “Top-up” = getting the BC to vote to extend the agreement. Very common in QLD — it adds significant value and bankability. 贷款最低要求：大多数贷款机构要求协议至少剩余15年——因此处于尚可区间（10–19年）的合同，一旦低于15年仍可能难以贷款。“续约”= 让BC投票延长协议期限，在昆士兰很常见，能显著提升价值和贷款可行性。

    Letting pool (POOL) 出租池规模

    PoolAssessment 评估
    30 or moreGood — excellent scale and diversity 良好——规模和多样性均优秀
    15–29Adequate — good, some vacancy risk 尚可——良好，有一定空置风险
    Under 15Risk — high per-unit vacancy risk 风险——单元空置风险较高

    ROI 投资回报率

    ROI = Net Income ÷ Price × 100%

    Typical PMR ROI is 15–25% — far above residential property (3–5%). If ROI shows as “—”, the price was not disclosed in the listing.典型PMR回报率为15–25%，远高于住宅投资（3–5%）。如显示“—”表示价格未披露。

    5. Due diligence checklist 5. 尽职调查清单

    Before making an offer 出价前

    • Request the full information memorandum (IM) from the broker. 向经纪人索取完整信息备忘录（IM）。
    • Confirm net income is audited (not just stated). 确认净收入已经过审计（非自报）。
    • Get the letting pool schedule — how many units, which owners. 获取出租池明细——单元数及业主名单。
    • Check units managed by outside agents (leakage you can recover). 检查由外部中介管理的单元（可争取回来的收入）。
    • Confirm the BC salary and annual CPI indexation clause. 确认BC薪资及年度CPI调整条款。
    • Review BC meeting minutes (last 2 years) for disputes. 查阅过去2年BC会议记录，了解潜在纠纷。
    • Confirm the agreement term remaining and top-up history. 确认协议剩余年限及续约历史。

    After signing (due diligence period) 签约后（尽职调查期）

    • Engage a PMR-specialist solicitor (not a general property lawyer). 聘请PMR专业律师（非普通房产律师）。
    • Engage a PMR accountant to verify all financials. 聘请PMR会计师核实财务。
    • Request 2-year trust account bank statements. 索取信托账户2年银行对账单。
    • Verify all letting agreements are current and signed. 核实所有出租协议均现行有效。
    • Inspect the condition of common areas — pool, gym, lifts, gardens. 检查公共区域状况——泳池、健身房、电梯、花园。
    • Meet the BC committee members in person. 与BC委员会成员面谈。
    Use a solicitor who specialises in MR — there are only ~10 firms in QLD who truly understand PMR contracts. Ask your broker for a referral. 务必使用MR专业律师——昆士兰只有约10家律所真正了解PMR合同，可请经纪人推荐。

    6. Financing 6. 融资方式

    PMR is treated as a commercial loan — different rules apply compared to residential.PMR属于商业贷款，规则与住宅贷款不同。

    Factor 因素Typical 典型情况
    LVR (loan to value) 贷款比例50–65% (less than residential) 50–65%（低于住宅贷款）
    Interest rate 利率~7–8.5% (commercial rate) 约7–8.5%（商业利率）
    Min contract remaining 最低剩余年限Most lenders require 15 years or more 大多数贷款机构要求≥15年
    Deposit required 所需首付35–50% of the business price 业务价格的35–50%
    Key lenders 主要贷款机构BOQ, ANZ, NAB (commercial desk), specialist MR brokers BOQ、ANZ、NAB（商业部门），MR专业贷款经纪人
    If buying MR+Unit, the unit is usually financed separately as residential (higher LVR). The split structure matters — get advice before signing. 购买MR+公寓时，公寓通常作为住宅贷款单独处理（更高LVR）。融资结构非常重要，签约前需专业建议。

    7. Red flags 7. 风险警示

    Skip immediately if any of these apply:出现以下任何一项立即跳过：

    • BC% over 80% — you are an employee, not a business owner. 你是雇员，不是生意老板。
    • Contract under 10 years — with no top-up in progress. 合同不足10年且无续约计划。
    • Multiplier over 6.5× — with no clear growth story. 倍数超过6.5倍且无明确增长逻辑。
    • Pool under 15 units — too concentrated, high vacancy risk. 出租池不足15个单元——过于集中，空置风险极高。
    • 100% BC salary — zero letting income = zero growth. 100% BC薪资——零租赁收入 = 零增长。
    • Projected income — must be audited actuals only. 预测收入——必须是经审计的实际数据。

    Investigate before proceeding:以下情况需仔细调查：

    • Price undisclosed (EOI / —) — ask why before requesting the IM. 价格未披露（EOI/—）——索取IM前先了解原因。
    • A large number of external-agent units — income leakage. 大量单元由外部中介管理——收入流失。
    • New complex (under 2 years) — no proven income track record. 新楼盘（不足2年）——无收入历史记录。
    • Recent price reduction — find out why. 近期降价——需了解原因。
    • BC% 70–80% — caution band, limited growth ceiling. BC% 70–80%——注意区间，增长空间有限。
    • Contract 10–19 years — adequate, but check it clears the 15-year lender minimum. 合同10–19年——尚可，但需确认是否达到15年贷款最低要求。

    9. Real operator experiences 9. 从业者真实经验

    These insights come from active PMR managers, brokers and buyers across Queensland forums, industry groups and published guides. They reflect real patterns — not hypotheticals.以下经验来自昆士兰州各论坛、行业群体及出版指南中的在职管理权经营者、经纪人和买家，反映的是真实规律，不是理论。

    Running the business day-to-day 日常经营

    • Phone never stops. Residents call at all hours — burst pipes at 11pm, locked out at 6am. New operators consistently underestimate the after-hours demand. If you value quiet evenings, budget for an after-hours call service (~$200–$400/mo). 电话永远不会停。住户随时都会打来——晚上11点爆管、早上6点锁门。新手经营者往往低估了非工作时间的需求。如果你重视安静的夜晚，考虑安排接听服务（约$200–400/月）。
    • Your relationship with the BC committee is everything. A supportive committee makes life easy; a hostile one can make every year stressful. Visit the complex and meet committee members before you buy — not after. 与BC委员会的关系至关重要。支持你的委员会让一切顺畅；对立的委员会会让每一年都很煎熬。在买之前去拜访综合体并与委员会成员见面——不要等到之后。
    • “The money is made in the letting, not the caretaking.” Your BC salary is the floor; your real income growth comes from recruiting more units into your pool. Experienced managers actively court external-agent units by being responsive and competitive on fees. “钱是在出租中赚到的，不是在物业管理中。”你的BC薪资是底线；真正的收入增长来自招募更多单元进入你的出租池。有经验的经营者会积极争取那些使用外部中介的单元。
    • Trust account discipline is non-negotiable. Every dollar of rent collected must flow through a separate trust account and be audited annually. Several managers have lost their licence over sloppy trust accounting — get proper software (PropertyMe, Console) from day one. 信托账户管理不容妥协。收取的每一分租金都必须通过独立信托账户流转，并每年审计一次。一些经营者因信托账务混乱而吊销牌照——从第一天起就使用专业软件（PropertyMe、Console）。
    • Staff or no staff? Many smaller complexes (under 50 units) are run owner-operator with no staff. Above ~80 units most managers bring in a part-time assistant. Factor this into your NI assessment — if the current operator has no staff but the complex clearly needs one, the stated NI is artificially high. 要不要员工？很多小型综合体（不足50单元）由业主兼职自营，没有员工。超过约80单元后，大多数经营者会聘用兼职助手。这需要纳入你的NI评估——如果当前经营者没有员工但综合体明显需要，则报告的NI是人为偏高的。

    On pricing & negotiation 定价与议价

    • Vendors always lead with projected income. Always ask: “Is this audited actuals, or a projection?” — a vendor saying “it’s on track to do $X” is not the same as two years of verified accounts. Walk away from projected-only listings. 卖家总是拿预测收入说事。务必问清楚：“这是经审计的实际收入，还是预测？”——卖家说“预计能做到$X”和两年经核实账目完全不是一回事。拒绝只有预测数据的物业。
    • Multiplier is negotiable — especially when metrics are mixed. If BC% is high (over 75%) or the contract is short (under 15 years), you have genuine grounds to push the multiple down. Brokers price for the best case; you buy for the realistic case. 倍数是可以议价的——尤其是当指标参差不齐时。如果BC%偏高（>75%）或合同偏短（<15年），你有实质理由压低倍数。经纪人按最好情况定价；你按现实情况购买。
    • Watch for “lifestyle premium” pricing. Coastal holiday complexes often carry a premium that pure numbers don’t justify. It’s fine if you want to live there — but don’t confuse lifestyle with investment merit. 警惕“生活方式溢价”定价。沿海度假综合体往往有纯数字无法支撑的溢价。如果你想住在那里，完全没问题——但别把生活方式和投资价值混为一谈。
    • Letting pool numbers can drift. A pool of 40 units sounds great — but if 8 have left in the past 12 months, the trajectory matters more than the snapshot. Ask for pool history, not just the current count. 出租池数量会变化。40个单元的出租池听起来不错——但如果过去12个月有8个离开了，趋势比快照更重要。要求查看出租池历史，而不仅仅是当前数量。

    Things that caught people off guard 让人措手不及的事

    • The BC can be your biggest risk. If you don’t get along with the committee, they can make your life difficult: refuse top-ups, give you bad reviews to unit owners, or push to terminate for minor breaches. Culture fit matters as much as financials. BC可以是你最大的风险。如果你与委员会关系不好，他们可以让你日子难过：拒绝续约、向单元业主给你差评，或以小违规为由推动终止合同。文化契合和财务指标同样重要。
    • Capital works levies can destroy short-term cash flow. If the building has deferred maintenance (old lifts, roof issues, pool resurfacing), the BC can vote a special levy. You don’t pay it — but owners do, and unhappy owners leave your letting pool. 资本维修征费会破坏短期现金流。如果楼栋有积压维护（旧电梯、屋顶问题、泳池翻新），BC可以投票征收特别税。你不用交——但业主要交，不满意的业主会退出你的出租池。
    • Vacancy is contagious. One empty unit doesn’t hurt much; five empty units in a holiday complex during the off-season can make your commissions drop 30–40% in a quarter. Holiday PMR needs a cash buffer of at least 3 months of living expenses. 空置具有连锁效应。一个空置单元影响不大；度假综合体淡季五个空置单元可能让你的佣金一个季度下降30–40%。度假PMR至少需要3个月生活费的现金储备。
    • “I wish I’d met the outgoing manager earlier.” Sitting down with the seller for a full handover (reservation system, maintenance contacts, quirky residents, BC dynamics) is invaluable — negotiate for a 1–2 week handover period in your contract. “我希望能早点与前任经营者见面。”与卖家坐下来进行完整的交接（预订系统、维护联系人、特殊住户情况、BC动态）非常宝贵——在合同中争取1–2周的交接期。
    Biggest consensus across operators: spend twice as long on the BC relationship and financials as you think you need to. The technical side of running a complex is learnable in weeks; undoing a bad deal or a hostile BC takes years. 从业者最大的共识：在BC关系和财务核查上花两倍于你认为需要的时间。运营综合体的技术层面几周内就能学会；但要解开一笔糟糕的交易或扭转敌对的BC关系，可能需要好几年。

    Documents required at purchase 购买时所需文件

    Your solicitor and accountant will collect most of these — but knowing what to expect prevents delays at settlement.你的律师和会计师会收集大部分这些文件——但提前了解能避免交割时的延误。

    From the vendor (seller) 来自卖方

    • Information Memorandum (IM) from the broker. 经纪人提供的信息备忘录（IM）。
    • Last 2–3 years of audited profit & loss statements. 过去2–3年经审计的损益表。
    • Last 2 years of trust account bank statements. 过去2年信托账户银行对账单。
    • Current letting pool schedule (list of all managed units + owner names). 当前出租池明细（所有管理单元及业主名单）。
    • Copies of all current letting agreements (signed). 所有当前出租协议的副本（已签署）。
    • Management agreement (caretaking agreement with the BC). 管理协议（与BC的物业管理协议）。
    • Letting agreement (the agreement governing your letting rights). 出租协议（管理你出租权利的协议）。
    • Confirmation of the remaining contract term. 合同剩余年限确认书。
    • Last 2 years of BC meeting minutes and financials. 过去2年BC会议记录及财务报告。
    • Schedule of BC levies (admin + sinking fund). BC征费明细（行政费+维修基金）。
    • List of approved contractors / maintenance suppliers. 已批准承包商/维护供应商名单。

    From the Body Corporate 来自物业委员会（BC）

    • Consent to assignment of management rights (BC resolution). 管理权转让同意书（BC决议）。
    • BC certificate confirming no outstanding breaches. 确认无未解决违规事项的BC证书。
    • Sinking fund forecast report. 维修基金预测报告。
    • Building & contents insurance certificates. 楼栋及财产保险证书。

    From the Office of Fair Trading 来自公平交易办公室（OFT）

    • Approved RLA Licence (your name, attached to this complex). 已批准的RLA牌照（你的名字，附属于该综合体）。
    • If applicable: company trust account setup documentation. 如适用：公司信托账户设置文件。

    Finance documents (if borrowing) 融资文件（如需贷款）

    • Formal loan approval letter from the lender. 贷款机构出具的正式贷款批准函。
    • Business valuation report (the lender will require this for the MR business component). 业务估值报告（贷款机构对MR业务部分的要求）。
    • If buying MR+Unit: separate residential loan approval for the unit. 如购买MR+公寓：公寓的独立住宅贷款批准。
    Timeline tip: allow 90–120 days from signing to settlement for PMR. The BC consent vote, OFT licence processing and finance approval all take time and cannot happen in parallel. Work backward from your target settlement date to ensure nothing holds you up. 时间线建议：PMR从签约到交割预留90–120天。BC同意投票、OFT牌照审批和融资批准都需要时间，且不能并行处理。从你的目标交割日期倒推，确保没有任何环节拖慢进度。
